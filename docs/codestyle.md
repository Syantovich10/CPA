# Кодстайл проекта

Документ описывает правила оформления кода в проекте CPA и инструменты, которые их автоматически проверяют.

## Инструменты

- **Prettier** — автоматическое форматирование кода (отступы, кавычки, переносы). Настройки: [.prettierrc.json](../.prettierrc.json).
- **Oxlint** — линтер, ловит ошибки и нарушения правил React. Настройки: [.oxlintrc.json](../.oxlintrc.json).

Для работы инструментов требуется Node.js версии 20 или новее.

## Правила форматирования (Prettier)

- Без точек с запятой в конце строк (`semi: false`).
- Одинарные кавычки для строк (`singleQuote: true`).
- Висячие запятые везде, где допустимо (`trailingComma: "all"`).
- Отступ — 2 пробела, максимальная длина строки — 80 символов (значения Prettier по умолчанию).

Эти правила не нужно соблюдать вручную — Prettier применяет их автоматически командой `npm run format`.

## Правила линтера (Oxlint)

- `react/rules-of-hooks` — хуки вызываются только на верхнем уровне компонента или другого хука (ошибка).
- `react/only-export-components` — из файла с компонентом экспортируются только компоненты, чтобы корректно работал HMR (предупреждение).

## Именование

- **Компоненты React** — `PascalCase`, файл называется как компонент: `App.jsx`, `Header.jsx`.
- **Хуки** — `camelCase` с префиксом `use`: `useAuth.js`, `useFormState.js`.
- **Остальные модули** (утилиты, api, конфиги) — `camelCase`: `i18next.js`.
- **Переменные и функции** — `camelCase`; константы верхнего уровня — `UPPER_SNAKE_CASE`.

## Структура папки src

- `components/` — переиспользуемые UI-компоненты;
- `sections/` — крупные секции страниц, собранные из компонентов;
- `hooks/` — пользовательские хуки;
- `api/` — работа с сервером (запросы, клиенты);
- `main.jsx` — точка входа, `App.jsx` — корневой компонент.

## Команды

```bash
npm run lint          # проверить код линтером
npm run lint:fix      # исправить то, что линтер умеет чинить сам
npm run format        # отформатировать все файлы
npm run format:check  # проверить форматирование без изменений
npm run check         # полная проверка: линтер + форматирование
```

## Правило перед коммитом

Перед каждым коммитом запускайте:

```bash
npm run check
```

Код попадает в репозиторий только если команда завершилась без ошибок.
