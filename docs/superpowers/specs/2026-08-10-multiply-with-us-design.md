# Multiply With Us — дизайн секции

## Цель

Добавить на главную страницу интерактивную секцию `MultiplyWithUs`, визуально соответствующую шести предоставленным desktop/mobile-референсам. Секция показывает отдельное предложение для медиабайеров, бизнесов и партнёров, получает контент на текущем языке через API и открывает существующую форму в модальном окне.

## Интеграция с проектом

- Перед реализацией ветка `feature/fourth-section` обновляется до актуального `origin/develop`, где уже находятся `Modal`, `ApplicationForm` и зависимости формы.
- `HomePage` хранит булево состояние открытия формы и передаёт секции callback `onApply`.
- Любая CTA-кнопка внутри секции вызывает `onApply`.
- `HomePage` рендерит одну общую связку `Modal` + `ApplicationForm`; закрытие работает через кнопку формы, клик по затемнению и `Escape` согласно существующей реализации.
- Существующий `Footer` импортируется из `@/components/Footer/Footer` и располагается после секции. На desktop он образует нижнюю полосу из референса, а на mobile остаётся скрытым в соответствии с текущим компонентом.

## Компоненты

### `MultiplyWithUs`

Отвечает за получение данных через `getMultiply` и `useApiData`, выбранную аудиторию и адаптивную раскладку. Начальное активное состояние — медиабайеры.

### `AudienceSwitcher`

Компонует три переключателя и передаёт каждому активное состояние и обработчик выбора. Для доступности контейнер получает семантику набора вкладок.

### `AudienceSwitchButton`

Отдельный компонент большой кнопки-переключателя из референсов. Принимает подпись, идентификатор аудитории, `isActive` и `onSelect`. Активная кнопка имеет жёлтую заливку, тёмный текст и обводку; неактивная — прозрачный фон, жёлтый текст и жёлтую обводку. Кнопка отражает выбранное состояние через `aria-selected` и не смешивается с CTA-компонентом.

### `AudienceCard`

Отдельный компонент сменяемой сиреневой карточки. Показывает два текстовых блока выбранной аудитории, две вертикальные стрелки и существующий `ThreeDButton`, импортированный из `@/components/Button/ThreeDButton`. Тексты и CTA изменяются вместе с активной вкладкой. Карточка связана с активным переключателем доступными `aria-controls`/`aria-labelledby`.

Компоненты `AudienceSwitcher`, `AudienceSwitchButton` и `AudienceCard` располагаются рядом с `MultiplyWithUs` в каталоге секции: они специфичны для этой секции, но остаются изолированными и тестируемыми.

## Данные и мультиязычность

- Контент карточки загружается из `GET /{lang}/multiply` через существующий endpoint `getMultiply`.
- Смена языка автоматически инициирует новый запрос благодаря `useApiData`.
- Ответ API — массив из трёх элементов в порядке `mediaBuyers`, `business`, `partners`; каждый элемент содержит `title` и `steps.step_1`/`steps.step_2`. Секция сопоставляет элементы стабильным идентификаторам по этому контракту.
- Подписи переключателей берутся из новых ключей `i18next` для аудиторий, поскольку английский API возвращает технические значения `for_media_buyers`, `for_businesses`, `for_partners`. CTA берутся из существующих `multiplyButtons`. Источником истины для двух основных текстов остаётся API.
- Поддерживаются `ru`, `en` и `ua` с существующим fallback на `en`.
- UI использует стабильные внутренние идентификаторы `mediaBuyers`, `business` и `partners`, поэтому переключение не зависит от переведённого текста.

## Раскладка

### Desktop

- Секция занимает минимум высоту viewport и использует фиолетовый градиент с существующим сетчатым фоном.
- Слева располагаются три переключателя и изображение `multiplysnake.png` у нижнего края.
- Справа находятся заголовок `MULTIPLY WITH US` и крупная сиреневая панель контента.
- Панель центрирует тексты, стрелки и 3D CTA; длинный русский и английский текст переносится без горизонтального переполнения.

### Mobile

- Переключатели идут вертикально над карточкой.
- Змея на mobile скрыта, как в референсах.
- Панель располагается одной колонкой, а заголовок `MULTIPLY WITH US` переносится под неё.
- Размеры шрифтов, интервалы и ширина CTA уменьшаются, сохраняя читаемость на ширине 320–430 px.

## Состояния и ошибки

- Во время первого запроса в области секции показывается существующий `Spinner`.
- При смене языка старые данные не выдаются за новый язык: отображается loading-состояние до завершения запроса.
- При ошибке API секция не падает: вместо динамической панели показывается локализованное короткое сообщение. Повторная попытка происходит при следующей смене языка или перезагрузке страницы; API hook в рамках этой задачи не расширяется.
- Переключение вкладок не закрывает модалку и не сбрасывает язык.

## Проверка

- Сборка, lint и форматирование проекта.
- Через Playwright: три состояния на desktop и три состояния на mobile, открытие и закрытие модалки каждой CTA, переключение языка и соответствующий повторный API-запрос.
- Визуальная проверка на 1440×900, 390×844 и минимальной ширине 320 px.
- Проверка отсутствия горизонтального скролла, обрезанного текста, перекрытий и выхода CTA за карточку.
- Клавиатурная проверка вкладок, CTA, закрытия модалки по `Escape` и возврата к начальному состоянию.

## Вне объёма

- Изменение полей, валидации или API отправки существующей формы.
- Создание отдельных модалок для разных аудиторий.
- Изменение desktop/mobile-политики отображения существующего `Footer`.
